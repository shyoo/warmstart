The first build of Warmstart made for anyone other than its author. It is a **release candidate**:
installed apps polling for updates will not see it, and the final `0.1.0` is what they will see
first.

## Upgrading from a pre-rename build

If you ever installed this as **Multi Agent Controller**, uninstall that app first (Windows: *Apps
› Installed apps*; macOS: drag it out of *Applications*). The application id changed with the name,
so the installer cannot replace it — it would sit beside Warmstart with the same icon, and its
shortcuts would keep opening an empty fleet. Your data is safe: Warmstart adopts the old data
directory on first start and keeps every project, worker and task.

## What's new

Everything, as far as a release is concerned. What it does:

- Runs coding-agent CLIs you already subscribe to — Claude Code, Codex, Antigravity, Muse — as a
  fleet, each account a *worker* with its own quota, each task a *run* in a pooled git worktree.
- Schedules against the subscriptions' windows: quota-aware routing, preemption before a window
  closes, prompt-cache-aware compaction timing, and a per-task cost with the arithmetic shown.
- Lands work for you under a finish policy (`commit-and-merge`, PR, or ask), never discarding a
  branch it could not land — those surface under **Loose ends**.
- Debate mode: several agents argue a question, an organiser resolves it, and the thread keeps the
  citations.
- Remote access: pair a second desktop over Tailscale and drive the fleet from there.

## Known problems

- **macOS** builds are signed and notarised, and the suites pass, but no real agent has yet been
  driven end to end from *this* bundle. That is what this candidate exists to find out.
- **Windows** builds are unsigned; SmartScreen warns on first run (see below).
- Linux is not built and not supported.
- An installed `-rc` will offer the final `0.1.0` as an update, but never a later `-rc`.
