# Multi Agent Controller — Session Handoff

Multi-agent controller: a scheduler that routes coding-agent tasks to the worker, session and moment
where they are cheapest. Electron shell + `orchestratord` daemon. Windows now; macOS/Linux built and
started in CI, never run against a real agent CLI.

**Current state + what to do next, not a changelog.** **Under 200 lines** — adding one means cutting
the line it obsoletes. Where every other fact goes: [`docs/README.md`](docs/README.md).

**Baseline (2026-09-04, measured):** typecheck · lint · build clean · `npm test` **1909/1911** across 95 files (2 POSIX-only skipped).
`test:daemon` **155/155**, `test:ui` **269/269** — measured, not carried forward; `test:pack` **19/19** carried forward. ⚠️ `test:pack` fails every check but its first if `release/` predates `src/`; its first check says so — run `npm run pack` and re-run rather than reading the rest.
CLIs here: claude 2.1.252 · agy 1.1.25 · codex 0.151.0 · local-llm 1.0.0 (qwen3-coder live tested). ⚠️ With none installed — the CI state — the daemon suite skips 5 checks, each with a stated reason.
Quality Review offers Auto and named eligible workers (revalidated server-side); t190 Run #1 quota probe repaired in DB (Gemini 5h 47%, 7d 27% → $0.24).

## What is true right now and not yet proven

- ⭐ **Plan & Split is built: a planner delegates, waits for nothing, and lands the whole** (2026-09-04, t182, `transient_docs/plan_and_split_2026-09-03.md` is the design of record). t178 designed it and shipped **no code**; the Plan button filed a `task.plan` with a title and a project and the composer hid every other control, which was honest only while a plan task was never dispatched. It now is. ⛔ **`kind: 'plan'` is dispatched like any other task** rather than handed to the unattended controller, which has no tools, cannot read the repository and cannot ask a question. Two turns: the planner reads, uses `ask_human`, and calls **`task_split`** once — which raises **one** approval for the whole split and blocks on it, because an agent told in its prompt to ask can forget and an agent whose tool call does not return cannot. On approval the pieces are filed atomically, the parent parks at `blocked` on one **`settled`** edge each, and its run ends `blocked` rather than `failed`. ⭐ **The wait bills nothing and holds nothing** — `retainedReservations` counts a slot as held by `awaiting_human` and by `running`-with-a-closed-session, and by neither for `blocked`. The last piece to settle re-admits the planner, which comes back with a table of every outcome and finishes the task. ⛔ **`task_deps.require`** is what makes that possible: `admit()` counted a prerequisite met only at `completed`, so a failed piece would have held its planner at `blocked` for ever — `settled` releases on `completed`/`failed`/`cancelled` and is written by `task_split` alone, so every edge already in the fleet keeps meaning *"do B after A"* means A succeeded. ⛔ **Nothing reaches the trunk until the plan is whole**: pieces are cut from the plan branch (`baseRef` takes the *task's* target) and merge back into it via a sixth strategy, **`merge-branch`**, which rebases, checks, proves ancestry and fast-forwards the target **ref** with a three-argument `update-ref` — a compare-and-swap — from inside the piece's own worktree, having first verified the branch is checked out in **no** worktree. `merge-local` structurally cannot do this: it merges inside the operator's own trunk checkout and would have required it to be sitting on the plan branch. ⚠️ It is chosen from **data** — does this task's resolved target differ from the project's — never from `task.kind`, and never in place of a policy that was not going to merge anyway. ⛔ **`landingTargetFor` has 24 production readers and all of them go through it**; two were not wiring at all. (a) The **trunk tripwire** refuses a verdict when a branch is empty and its target moved — under a split a sibling landing onto the shared plan branch is exactly that, constantly and by design, so movement attributable to a sibling's recorded `landed_head_sha` is subtracted and only the unexplained remainder fires. ⛔ Not an exemption for children: a piece committing onto the plan branch instead of its own branch is t17 one level down. (b) **`resolveRange`** would have graded a piece over `merge-base(main, piece)..piece` — the planner's commits plus every earlier sibling's work — producing a quality score indistinguishable from a real one. ⛔ **The composer now draws two labelled rows** (D5): **Planner** (worker, model, effort, reuse, finish, priority, dependencies, attachments) and **Each piece** plus a fan-out pill whose number is written into the task's **mandate**, so there is never a second invisible cap; only Draft and the schedule clock stay task-only. ⭐ **t190 aligns the composer buttons in a table** (`[+] [Task] [P2] [Depends on] [Reuse] [Commit.Verify..] [Auto Worker] [CLI default]`; Planner vs Each Piece with `[Workers]` multi-worker and per-worker models) and ensures child work defaults to parent's planner branch and merges cleanly without touching `main`. ⚠️ 41 new checks — `split.test.ts` (22), `mergebranch.test.ts` (9, **real git**), `landingtarget.test.ts` (7), `composerprefs.test.ts` (3). ⭐ Both corruption guards were watched going **red** before being trusted green, and the practice found a real defect first: `applySplit` wrote inter-piece edges with `addDependency`, which deliberately does not re-admit, so a piece that should have waited sat at `ready` and would have run in parallel with the piece it depended on — silently. ⚠️ **None of it has run against a live agent**, which is next step 1 and the only way to see the three things unit tests cannot: whether the planner delegates instead of building, whether the approval card is answerable in one click, and a real `merge-branch` landing with a sibling in flight.
- ⭐ **The first real Plan & Split ran, and everything it broke is fixed** (2026-09-04, t197). t182 shipped the feature unit-proven and unflown; one live split found seven faults, five of which were silent. ⛔ **The pieces were routed to whatever the fleet felt like.** The composer's Each piece row sent `workerIds` and per-account models, `checkConstraints` validated them, and `applySplit` read only the singular `workerId` beside them — so every piece was filed with an *empty* `constraints`, went through the ordinary dispatcher and was handed the largest model in the fleet for work chosen to be small. Nothing failed; the bill was just wrong. `pieceConstraints()` now resolves the whole answer in one place (`childDefaults` first, the planner's `constraints.pieceConstraints` behind it) and `chooseTarget` reads `workerIds` as a **gate** — a candidate outside the list is discarded, never merely scored lower. ⛔ **A piece was told to land on `main`, and it did.** Both recovery prompts — `resolveConflictOnTask` and `resolveRetryOnTask` — resolved their base from the *project* rather than the task, so a stuck piece was instructed to `git rebase main` and commit there while its planner waited on a branch that never moved. A wrong ref in a prompt is not a wrong sentence; it is work on the wrong branch by an agent doing as it was told. `switchResidentBranch` had the same omission, one call site from `baseRef`'s own warning about it. ⛔ **A plan branch left checked out in a pooled slot wedged the whole split for ever** — `merge-branch` refused every piece, the pieces rested at `awaiting_human`, which is not a settled status, so the planner stayed `blocked` on children that could never settle. `merge-branch` now frees **this tool's own pool members** off the target first, before the rebase (a rescue commit moves the target, and parking later would fail the ancestry proof it had just enabled); the operator's trunk and any hand-made worktree are still refused. That is also the answer to *"can one workspace deadlock a split?"* — no: a `blocked` planner reserves nothing, so the pieces it waits for can always be dispatched. ⛔ **A pill's menu was clipped to a few pixels** in Plan & Split, because `overflow-x: auto` makes the row a scroll container in *both* axes; menus now render into a portal at the document root and `menuposition.ts` flips them above the pill when the window has no room below. ⭐ **The thread says what it is looking at**: `type` (`Task` / `Plan & Split`), `parent` for a piece — ⛔ lineage is *not* a dependency, the edge points the other way, so no existing list could ever name it — `pieces` with every outcome, and `each piece` reading back the accounts and models the composer set. A subtask is marked **➥** rather than `└`, which claimed to join whichever row the current sort put above it. ⚠️ 37 new checks across nine files; the two corruption-adjacent ones (pooled parking, prompt refs) were watched red first. ⛔ `test:ui` had four checks still asserting the *two-row* Plan & Split composer that f894431 replaced with one `Piece`-prefixed row — stale since that commit, and only found because t197 was the first session to run the suite; they now pin the naming, which is what tells planner and piece apart today.
- ⭐ **Provider outages (Claude 529, Codex backend 404) and resume failures spare workers and retry** (2026-09-03, t153/t157, [`docs/adapters.md`](docs/adapters.md)). (a) Claude 529 and OpenAI `backend-api/codex/responses` outages are classified as `overloaded`: the run ends `preempted`, worker health is untouched, and tasks automatically retry with exponential backoff (1m, 2m, 4m; up to 3 attempts). (b) When a warm run (`startedWarm`) fails on arrival (DOA), the failed conversation prefix is cleared (`context_tokens = 0`) and the task restarts cold rather than quarantining healthy accounts or looping on a broken thread; and Codex error items/turn failures decode their messages into backscroll.
- ⭐ **Codex usage limit pauses at `paused_quota` with reset time and auto-resumes** (2026-09-03, t168/t174, [`docs/adapters.md`](docs/adapters.md)). Measured from t168: Codex answered *"The agent reported a failure (error): You've hit your usage limit... or try again at 12:03 PM."* `openai-compatible` now implements `outOfQuota`. `quotaFailurePark` reads `resets_at` from `windowResetsAt` or parses `parseQuotaResetTime` (e.g. `try again at 12:03 PM`), parking tasks at `paused_quota` with `notBefore` and `run.outcome = 'preempted'`. When the reset time passes or probe quota recovers, `resumeQuotaPaused` auto-resumes to `ready`.
- ⭐ **A task that settles admits its dependents from inside `setStatus`, and a tick sweeps for the ones that were missed** (2026-09-04, t198, `docs/architecture.md` §4). Admitting was the *caller's* job and most of the seven paths that settle a task never did it: `relandTask` — the button that drives a twice-failed landing home by hand, which is exactly how t192 finished — and `decomposeTask` skipped it outright, and on the `failed` and `cancelled` paths the `settled` edge `task_split` writes (there so a planner is woken by the pieces that *failed*) was released by nothing outside `cancelTask`. Measured: t192 landed as `1a274207` at 14:40Z and t193 was still `blocked` behind it, because a `blocked` task holds no clock, no worker and no session — **nothing about it ever expires**, so one missed event strands it for good. `setStatus` now admits on the transition into `completed`, `failed` or `cancelled`, whichever path wrote it (`admit()` still decides per edge, so an ordinary `completed` edge is unmoved by a failure), and `admitBlocked()` on the tick re-reads every blocked row against the world — repairing the rows the old versions stranded, on the first tick, with no migration, and logging at **warn** when it releases one, because a release there means a bug above it. ⚠️ Admission lands a moment *before* the settling task's workspace is released, so a dependent can reach `ready` and find the pool full; that is a hold and the next tick runs it. ⚠️ Unproven end to end: L1-tested in `dependents.test.ts` (the central cases go red without the hook) — no packaged app has yet been watched releasing a real dependent.
- ⭐ **Filing a task starts with the prompt, and the settings remember** (2026-09-02, t128). The New Task form asked five labelled rows of questions before the one field anybody came here to fill in, and every one of them was answered the same way on almost every task — so the first thing a person met was five controls they were about to leave alone, and `inherit (commit, verify and merge locally)` recomputed itself from the project on every open, which made overriding one a thing you did again on the next task and the one after that. The prompt is now first and the settings are a row of **pills** under it (`Pill.tsx`, `NewTask.tsx`), each showing an *answer* rather than a label: `P1` `Task` `Dep` · `Reuse` `Commit·Verify·Merge` · `Auto` `Model` `Effort`, with Draft/Send/⏱ inside the box. ⛔ **Last-selected beats inherited.** Inheritance supplies the first value a control ever shows and nothing after that; what is inherited is drawn **dimmed** rather than carrying eleven characters of the word, and the tooltip still names the tier. ⛔ Model and effort are remembered **per account** (`composerprefs.ts`) — a model id belongs to one CLI, so one remembered slot would hand the next adapter an id it cannot start on, which is why the old form cleared the field on every worker change and threw the choice away with it; a remembered id is re-checked against `model.options` and falls back to inherit rather than being sent. ⚠️ Dependencies and the schedule are deliberately **not** remembered: both are facts about one piece of work, and a composer that quietly re-armed *in 4 hours* would file a task that goes nowhere. ⚠️ **Multi-task and Conversation are not stubbed** on the kind pill; `Plan` is the existing decomposition path under its own name. ⭐ 17 unit checks and 15 new `ui.test.mjs` ones drive the pills, the menus and the remembering in the built app.
- ⭐ **A run has a price in dollars, and a task has a total** (2026-09-02, t130, `docs/cost-model.md` §13). Everything this tool measured was tokens or quota percent, and neither answers *what did that task cost me*. A `plans` block in each `costmodels/*.json` names the subscription catalogue and the window its money divides over, and `CostModel.priceOfWindowUsage` holds the only arithmetic: `monthly_usd × pool_share × (days/30.4375) × (percent/100)` — $20/month over 7 days is **$4.5996** per full window, so 5% of a week is **$0.230**. ⛔ **`billing_window.match` is matched against the ids the *adapter emits*, never the ids in the same file's own `quota.windows`** — measured 2026-09-02, claude-code declares `5h`/`7d` and emits `session`/`weekly_all`, antigravity declares `weekly:claude-gpt` and emits `weekly:claude-and-gpt`; matching declared ids would have priced nothing at all, silently. **Migration 35** stamps `plan_id`/`plan_raw`/`plan_source` per run and backfills in four rungs — window **shape**, nearest shape-resolved **neighbour**, the vendor's **identity** string, then the provider's **default**, ⚠️ which is always a *paid* plan because guessing free prints `n/a` over real money. ⭐ **The Codex free→paid switch is recoverable exactly** from the shape: every codex run to 2026-09-01 21:28Z carried one `30d` window and every one after carried `5h`+`7d` — 8 and 16, no overlap — which is strictly better than deducing it from the model name, since the 8 free-era runs recorded no model. ⛔ **The plan is stored; the price is not.** A run's dollars change the moment a *later* overlapping run is found, so `price.ts` cuts the timeline at every reading (`quota_samples` **plus** each run's own snapshots) and splits each segment's delta by how much of it each open run covered — the operator's worked example (0/5/15/17% over two overlapping runs → **10%** and **7%**) is asserted to the number. ⛔ A segment with **no** run open is dropped, never redistributed: that is the operator's own use of the account. ⛔ A segment where the percentage **falls** is a rollover and every run across it is `n/a`, not clamped — `resets_at` is useless for this (384 forward moves against 6 percent-drops over 1,263 samples). ⚠️ **Antigravity's 80:20 pool split is a judgement call**, not a published figure (Gemini $16, Claude/GPT $4); the shares sum to 1 so a week that fills both pools still reports one week. ⛔ **`n/a` is never `$0.00`** — five reasons, five tooltips — while a window that measurably did not move *is* `$0.00`. Tasks table and thread both read `Price` over a faint token line, with `*` for a split and `≥` for a total missing runs. ⚠️ 76 new checks (`price` · `costplans` · `runprice` · `Price` · `format`) + 4 in `ui.test.mjs`; **no figure has been read against a real invoice**, and the whole thing has not run in flight. ⭐ **Money is now the primary indicator, and it is layered** (2026-09-04, migration 43): `usd` = `subscriptionUsd` (the amortised share above) **+** `overageUsd` (money a vendor really billed — Claude extra usage, Antigravity/Codex credits — attributed off the new `spend_samples` table), with `listUsd` (the API-equivalent price) carried on the run and ⛔ **never summed in**. ⛔ `null` is *not known*, never `0`, in all three: one layer missing gives the other alone with `basis` saying **lower bound**, both missing is `n/a` — a sixth reason, `no_meter`, for a run nothing meters at all. ⭐ `attribute()` now takes a `direction`: a credit purse **falls** as money is spent and a **top-up is a rollover**, which is one algorithm and not two — the falling worked example asserts the same 10%/7%, and `'rises'` stays the default so every prior call and test is unchanged to the number. ⭐ **And the table is now filled, from two vendors whose signals were already reaching this daemon and being dropped** (2026-09-04, t193). An adapter declares a `spendProbe` capability — `none` · `cli` · `config-cache` · `stream` — and may implement `probeSpend`; nothing anywhere branches on an adapter's name. `spend.ts` is the store, shaped like `quota.ts`'s: a probe that ran and found nothing writes a row with an `error` and no balance, a reading is dated by the **vendor's** timestamp, every landed row bumps the pricing epoch, and re-reading one reading writes nothing. ⛔ **Codex** (`config-cache`): `credits.balance` out of the same rollout the quota fallback reads — parsed since M5 and until now discarded — as one `codex_credits` meter, `balance_falls`, `usdPerUnit: null` because **no conversion may be invented**, and an `unlimited` account gets no meter and a reason. ⛔ **Claude Code** (`stream`, and therefore *no* probe): `result.total_cost_usd` → `runs.list_usd`, which **replaces rather than adds** because it is cumulative for the invocation — and on a subscription it is the API-equivalent **list** price, never money out of pocket; `rate_limit_event`'s `isUsingOverage`/`overageStatus` → `runs.on_overage`/`overage_status`, ⚠️ nullable, where null is *the vendor said nothing* and is not `false`. ⛔ The money probe rides the **quota poller's own pacing** rather than a second timer, and a probe that throws is recorded as a failed reading and never costs the account its window reading. ⭐ **The operator surfaces agree with it**: Analytics › Cost Model leads with the three layers and a live spend-meter table, its factor table says whether each multiplier was learned in **dollars or tokens** (`learnedFrom`, published rather than implied), and a task’s hover names the overage inside its total and the list price outside it. ⚠️ Unproven in flight: L1 only (`spend.test.ts`, `codex-quota.test.ts`) — **no live account has been probed**, so no real balance, list price or overage flag has been seen, and the estimator’s `medianUsd`/`usdSamples` are declared and honestly empty. ⛔ No figure here has been read against a real invoice.

## Standing decisions worth not relitigating

⛔ The invariants live in `AGENTS.md`; these are the ones most re-argued by somebody who has not read it:
- **Daemon, not all-in-Electron.** The premise is unattended progress across quota windows.
- **Deterministic scheduler; LLM on judgment events only.** A loop running every 10s for weeks must not bill anything, and the fleet survives with no controller at all.
- **PTY-hosted CLI, transcript for state.** We own stdin, so `/compact` is a function call. ⚠️ ANSI parsing determines state in exactly one declared place - a quota reading. Never a session's state.
- **Capabilities and objectives are data.** No `if (adapter === …)`, no `if (mode === …)`.
