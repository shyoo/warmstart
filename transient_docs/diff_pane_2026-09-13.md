# The Diff pane — t425, 2026-09-13

Dated design record and implementation plan. Status lives in `HANDOFF.md`; the maintained
reference is `docs/ui.md` (routes, the component map, what a pane may draw).

## The report

> When I click the diff (either at "Changes in this task" or the commit id in the side pane), it
> shows the diff in-line in the component. That is a problem in the side pane, whose width is too
> small. Instead, add a new pane, like Claude Code's, that opens on the right side and is closable,
> when the user clicks a commit to see the diff.

What it replaces, measured in the code as of `46d6470`:

| Where | What it does today | Width it gets |
|---|---|---|
| `thread/DiffPanel.tsx` — **Changes in this task** | `<details>` in the thread column; each file row expands its own patch inline, unified or side by side | the thread column: `minmax(0,1fr)` of a grid that also holds a 300px ledger |
| `TaskThread.tsx` `CommitRow` — the ledger's *commits in this task* | the sha is a button; pressing it draws `CommitDiff` (the same file list and patches) inside the ledger box | **300px**, minus box padding — which is the report |

## The decisions the operator made

Asked with `ask_human`, 2026-09-13, one at a time:

| Decision | Chosen | Why it mattered |
|---|---|---|
| Name | **Diff pane** (`DiffPane`, `.diffpane`) | *detail* is already the task screen (`.detail-grid`) and *review* is the peer quality review in `glossary.md`; both would have collided |
| Where it lives | **Shell-level**, a new column right of `.main` in `App.tsx` | Full window height, own scroll, its own drag handle, survives tab switches. The screenshot's layout |
| What stays inline | **File list stays; patches move** | The gate keeps its file list beside *Land*; clicking a file, or *Open in Diff pane*, opens the pane at that file. The ledger's sha opens the pane and no longer expands inline |
| Layout | **Stacked, with a budget** | Every file in one scroll under a sticky header, each collapsible; auto-expanded from the top until a budget is spent, the rest load on click |
| Context lines | **Hunks now, full-file later** | The existing RPCs return git's hunks. The pane draws a collapsed *N unmodified lines* row between hunks from the `@@` headers alone — no extra git call. `context: 'full'` on the RPC is a follow-up |
| Lifetime | **Follows the route** | Closes when the route leaves the task it was opened for; survives that task's tabs and Back/Forward within it. Opening and closing is not a history entry |
| Deliverable | **Plan, then implement** | this document, then the code |

## The design

### State, and who owns it

```ts
// src/renderer/src/lib/diffpane.ts
export type DiffSource = { kind: 'branch' } | { kind: 'commit'; sha: string }
export interface DiffPaneRequest { taskId: string; source: DiffSource; focusPath?: string }
```

One `useState<DiffPaneRequest | null>` in `App.tsx`, beside the other shell-owned things
(`addingProject`, `addingTask`). It is handed down through a **context** (`DiffPaneContext`,
`useDiffPane()`), not props: `TaskThread` is mounted from four routes (project thread, unassigned,
quality review, conversation history) and threading a callback through `Project` and the other three
is four edits for one fact. The hook returns `{ request, open, close }`.

⛔ **Follows the route, decided by a pure function.** `paneRouteTaskId(route)` reads the `taskId`
every task-carrying route already has; an effect in `App` closes the pane when that stops equalling
`request.taskId`. Opening one commit after another on the same task *replaces* the request. Pinned
in `diffpane.test.ts`.

### The shell

`.shell` grows two columns: `sidebar | handle | main | handle | diff pane`, with
`.shell--diffpane` switching the template to `var(--sidebar-w) 4px minmax(0,1fr) 4px var(--diffpane-w)`
and the closed state leaving the last two at 0. `.main` stays pinned to column 3 for the reason the
comment there already gives. The sidebar-hidden variant composes: `0 0 minmax(0,1fr) 4px var(--diffpane-w)`.

`SidebarResizer` becomes a generic `PaneResizer` (variable, storage key, default, bounds, and which
edge the pane hangs from), with `SidebarResizer` a two-line wrapper so nothing that reads
`--sidebar-w` changes. The diff pane's width is `window.innerWidth − clientX`, clamped to
**[360, 60% of the window]**, default **560px**, remembered in `localStorage` (`diffPaneWidth`).
A per-display preference, like the sidebar's.

### The pane (`components/DiffPane.tsx`)

```
┌─ t425 · a591e0e  Narrate what a dispatched agent…   [Single column|Side by side]  ✕ ─┐
│ ⚠ warnings (separate commits, truncated list, uncommitted files)                       │
│ ▾ landing.md                                                       +6 −0   ← sticky   │
│   ⋯ 586 unmodified lines                                                              │
│   @@ -587,6 +587,12 @@ … rows …                                                        │
│ ▾ remote.md                                                        +6 −4              │
│ ▸ HANDOFF.md                                                       +2 −2   (collapsed)│
└───────────────────────────────────────────────────────────────────────────────────────┘
```

- **Reads the same RPCs the inline views read**: `task.diffSummary` + `task.diffFile` for a branch,
  `task.commitDiff` + `task.commitFile` for a commit. A branch pane re-reads on a `task.changed`
  event for its task; a commit is immutable and is read once.
- **Budget** (`initialExpansion(files)` in `lib/diffpane.ts`): auto-expand from the top while the
  running total of counted lines stays under **1,500** and the count of expanded files under **12**;
  binary and generated files never. A `focusPath` is always expanded and scrolled to. ⚠️ A file's
  patch costs one `git` call, and this is the ceiling on how many a click fires.
- **Unmodified rows** (`lib/hunks.ts`): `parseHunkHeader` reads `@@ -a,b +c,d @@`;
  `gapBefore(prev, cur)` is `cur.oldStart − (prev.oldStart + prev.oldLen)`, or `oldStart − 1` for the
  first hunk. Drawn as a `⋯ N unmodified lines` row between hunks in both layouts. The tail of the
  file is unknown from a patch and is not drawn — that is the follow-up's job.
- **Every line is still a text node.** The pane reuses `PatchBody`/`SplitBody` out of
  `DiffPanel.tsx` unchanged; the `⛔` at the top of that file applies to it in full.
- The unified/split toggle moves into the pane header, still `prefs.ts`'s `diffView`.
- Header: `t<seq> · Changes in this task` for the branch, `t<seq> · <sha8>` and the subject for a
  commit. `✕` closes; `Esc` closes when focus is in the pane.

### What changes inline

- `DiffPanel` keeps its `<details>`, its warnings and its file list. A file row is now a button that
  opens the pane at that file; the header gains **Open in Diff pane**. `FileRow`'s inline expansion,
  `DiffFiles`'s toggle and `CommitDiff` go — the pane is the one place a patch is drawn.
- `CommitRow`'s sha button calls `open({ taskId, source: { kind: 'commit', sha } })` and shows
  `aria-pressed` while the pane is on that commit. Its eager totals stay.

### Out of scope, on purpose

`src/mobile` (the phone has no room for a second pane); full-file context; opening a file in an
editor; anything that interprets patch text.

## Tests

- **L1**: `lib/diffpane.test.ts` (route-following, budget, replace-on-reopen),
  `lib/hunks.test.ts` (header parse, gaps, new-file hunk `-0,0`).
- **L3** (`test/ui.test.mjs`, *the diff a person reads before pressing Land* and *the diff of one
  commit a task landed*): a file row in the inline list opens `.diffpane` on the branch at that file;
  pressing the sha opens it on the commit, the shell's `.main` narrows by the pane's width, the file
  is auto-expanded with its patch as text nodes only, `✕` closes it, the inline `.diff-panel` still
  lists files after the task settles, Back to the Tasks tab keeps the pane (the route still names
  the task) and Dashboard closes it. Both sections run on the project thread route, so this is one
  of the few project-tab changes `test:ui` reaches; the other three `TaskThread` mounts share the
  context and stay hand-tested.

## What was measured after building it

Driven in the built app (2026-09-13, `scripts/_t425_shot.mjs`, deleted) on a fixture of three
files: the pane opened at **560px** with the work narrowed beside it; `⋯ 7 / 73 / 23 / 36
unmodified lines` rows between hunks matched the `@@` headers; both layouts drew. ⚠️ The scroll to
a focused file waits until every open file above it has settled — scrolled on mount, the first
patch to land above pushed it out of view.
