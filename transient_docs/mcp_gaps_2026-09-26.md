# MCP capability gaps — implementation plan (t706, 2026-09-26)

Design of record for: surfacing each worker's MCP capability in Settings > Workers,
documenting what MCP-less agents cannot do, and deciding whether planners must be
MCP-capable. Status: operator chose **badge plus composer-time hint** (no planner
gate) — §4 items 1–2 and the Delegate hint are implemented; item 3 (planner gate)
is declined, G3 stands as documented behaviour.

## 1. Measured starting point (read off the code, 2026-09-26)

`AdapterCapabilities.mcp` (`src/shared/protocol.ts:1206`) is declared per adapter,
never branched on by name (AGENTS.md invariant):

| Adapter | `mcp` | Why (per `docs/adapters.md` + code comments) |
|---|---|---|
| `claude-code` | true | `--mcp-config` per session |
| `openai-compatible` (Codex) | true | per-session `-c mcp_servers.<name>…` overrides (t618) |
| `antigravity-cli` | false | `agy mcp add` registers globally, cannot carry per-session identity |
| `muse-code` | false | `mcpServers` lives in per-account `settings.json`; two pooled sessions would share one identity (t676) |
| `local-llm` | false | function-calling bridge only |
| declarative (`external.ts`) | false | refused by `external.test.ts` (`docs/mcp.md` §2) |

## 3. Gaps found while writing this plan

- **G1. No MCP signal in Settings > Workers.** The renderer shows no `mcp` state anywhere
  (verified 2026-09-26: zero `mcp|MCP` hits in `Workers.tsx`). An operator cannot tell
  that an Antigravity or Muse worker will ask via text, need manual folder attach, and
  cannot delegate or land by tool.
- **G2. Nothing gates an MCP-dependent task onto an MCP-capable worker.** Zero
  `capabilities.mcp` references in `split.ts`, `scheduler.ts`, `routingdecisions.ts`
  (verified 2026-09-26). A Plan & Execute / Plan & Split planner, or a delegation-enabled
  task, can be dispatched to an MCP-less worker with no warning.
- **G3. An MCP-less planner is not even told to plan.** The `mcpLess` prompt branch
  (`prompt.ts:1059`) handles follow-ups and debate phases but has **no `planPhase` arm** —
  `handoffInstruction` / `planningInstruction` live only in the `mcp` branch
  (`prompt.ts:1031-1034`). An MCP-less agent filed as a planner gets the generic work
  instruction and would do the work itself rather than split it. G2 is the gate; G3 is
  what happens without it.
- **G4. Debate does not need the gate** — organizer and seats already work through the
  terminal fallback (t618). Any planner-only restriction must exempt debate (and note
  the organizer/seat `native MCP` vs `terminal fallback` labels already exist).

## 4. Proposed implementation (not started)

1. **Workers UI badge (small).** One badge per worker row in `Workers.tsx`, read off the
   worker's adapter `capabilities.mcp`: `MCP tools` vs `No MCP tools`, with a tooltip
   naming the fallbacks (§2: text questions, manual folder attach, no tool delegation,
   Land button instead of `land_work`). Capability-not-name: the badge reads the
   capability, so a future adapter that gains MCP lights up with no UI change.
   Owes: `docs/ui.md`.
2. **Composer hint (small).** When filing Plan & Execute / Plan & Split, or toggling
   Delegate on, while the pinned worker (or all routable candidates) lack MCP, show a
   one-line note naming the consequence — not a block, unless D2 says block.
3. **Planner gate (medium — needs D2).** Options: (a) routing-level eligibility at the
   dispatch call site (NOT `eligibility.ts`, which is account-only by design — a
   task-kind gate belongs at the call site per that file's own header); (b) prompt-level
   fallback teaching an MCP-less planner to emit the split as text for the person to
   file (mirrors `delegateCommandPrompt(mcp=false)`); (c) leave un-gated and rely on
   the badge + hint. Note the scheduler-zero-tokens invariant: whatever is chosen must
   stay deterministic — no LLM judgment in the gate.
4. **Tests.** L1 for the badge mapping (capability → label, incl. a hypothetical
   newly-MCP adapter needing no UI change) and for the gate/fallback choice; existing
   `split.test.ts` / debate suites must stay green.

## 5. Cost / risk notes

- Worker MCP configs are frozen per session and shared per project (`mcp.md` §2); the
  badge is display-only and costs no prompt-cache prefix.
- A hard planner gate shrinks the routable pool on installs with only Antigravity/Muse
  workers — on such installs Plan & Execute would hold instead of run. That is the
  main cost of option (a).
